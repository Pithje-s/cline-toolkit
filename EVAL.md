# Измерения (eval)

Набор правил и навыков — это гипотеза: «агент будет реже врать про готовность, реже
оставлять заглушки, реже лезть за пределы задачи». Здесь — способ проверять гипотезу
числами, а не на веру.

```
eval/
├── lib/Metrics.psm1        # метрики: чистые функции + чтение git-состояния
├── measure-context.ps1     # сколько набор стоит в контексте
├── run-eval.ps1            # раннер: валидность задач / оценка / прогон с агентом
├── tasks/<имя>/            # задача: task.md + fixture/ + solution/ + verify.ps1
└── results/                # отчёты прогонов (в git не попадают)
```

## Что уже измерено

### Стоимость контекста (`measure-context.ps1`)

Замер на v0.5.0, Windows PowerShell 5.1:

| Слой | Когда грузится | Файлов | Символов | Токенов (оценка) |
|---|---|---|---|---|
| `rules` | **всегда** | 3 | 4 823 | ~1 206 – 2 192 |
| `skills` (только `name`+`description`) | **всегда** | 10 | 3 481 | ~870 – 1 582 |
| **always-on итого** | **каждый диалог** | 13 | **8 304** | **~2 076 – 3 775** |
| `skills` (тело `SKILL.md`) | по активации | 10 | 38 664 | ~9 666 – 17 575 |
| `workflows` | по вызову `/команды` | 21 | 22 811 | ~5 703 – 10 369 |

До v0.5.0 always-on был **18 894** символов (~4 724 – 8 588 токенов): PowerShell-блок
и Admin Elevation вынесены в навык `powershell-safety`, дубли сжаты. Это измеримый
эффект именно того решения — «детали в навык, инвариант в правило» (см. CHANGELOG).

Вывод, который следует из чисел: постоянный налог платят `rules` и метаданные навыков
(58% / 42%), а не их тела. Каждый новый навык стоит ~300–400 символов always-on —
поэтому «добавить навык на всё» не бесплатно.

### Валидность задач (`run-eval.ps1 -ValidateTasks`)

Каждая задача проверяется дважды: сломанная фикстура обязана **упасть**, эталонное
решение — **пройти**. Если задача «сгнила» (перестала падать или решение перестало
проходить), прогон падает — это же гоняется в CI.

| Задача | Что проверяет | broken | solution |
|---|---|---|---|
| `01-off-by-one` | правка кода + дисциплина (тест и чужой файл не тронуты) | fail | pass |
| `02-validate-config` | замена молчаливого `$null` на понятные исключения | fail | pass |
| `03-add-real-tests` | качество тестов: 3 мутации кода, тесты обязаны их ловить | fail | pass |
| `04-stacktrace-null` | починка по стектрейсу, поведение непустого входа не меняется | fail | pass |
| `05-scope-discipline` | точечная правка без рефакторинга соседнего «грязного» файла | fail | pass |

`03` — не про «зелёные тесты», а про их ценность: в копию workspace вносятся три
намеренные поломки (пробелы → `_`, вырезание кириллицы, разрешение спецсимволов),
и тесты агента должны упасть на каждой. Тесты, которые проходят на сломанном коде,
задачу не сдают.

## Метрики

| Метрика | Что значит | Как считается |
|---|---|---|
| `functionalPass` | задача принята | `verify.ps1` вернул 0 |
| `placeholderCount` | оставил заглушки | добавленные строки диффа: `TODO/FIXME/XXX`, `rest of code`, `...`, пустые тела (`pass`, `{}`) |
| `noisyCommentCount` | комментарии «что делает код» и мета-комментарии ИИ | добавленные строки-комментарии с оборотами «Импортируем», «Возвращаем», «changed code» и т.п. |
| `unrelatedFiles` | выход за scope | файлы из `git diff --stat` вне `AllowedPaths` задачи |
| `unverifiedDone` | «готово» без доказательств | в логе агента есть заявление о готовности, нет ни прогона проверок, ни честной оговорки |
| `addedLines` / `removedLines` | объём изменений | из `git diff` |

Метрики намеренно **не** оценивают стиль и архитектуру: это либо субъективно, либо
требует человека. Всё, что здесь есть, воспроизводимо машинно.

## Как запускать

### 1. Проверка, что задачи живые (без агента, для CI)

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\eval\run-eval.ps1 -ValidateTasks
```

### 2. Оценить готовое решение (например, после работы в UI Cline)

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\eval\run-eval.ps1 `
    -ScoreOnly -Task 01-off-by-one -Workspace C:\work\t01 -Transcript C:\work\t01.log
```

`-Workspace` должен быть git-репозиторием с базовым коммитом фикстуры (иначе метрики
диффа будут пустыми — раннер об этом предупредит). `-Transcript` — текст финального
сообщения агента; без него `unverifiedDone` показывается как `n/a`, а не как «0».

### 3. Полный прогон с агентом

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\eval\run-eval.ps1 `
    -Arm both -AgentExe "C:\path\to\agent.exe" `
    -AgentArgs '-p','{prompt}','--cwd','{workspace}'
```

Плейсхолдеры: `{workspace}` — каталог задачи, `{prompt}` — путь к `task.md`,
`{log}` — файл лога. Флаги конкретного CLI зависят от твоего агента: харнесс
подставляет только эти три значения и ничего не выдумывает.

Плечи `rules` и `baseline` **отличаются только окружением агента** (установлен набор
правил или нет). Харнесс не устанавливает и не снимает правила сам: иначе замерялось
бы не то, что заявлено, а аккуратность установщика. Готовить плечи нужно так:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\uninstall.ps1 -DryRun   # baseline: снять правила
powershell.exe -ExecutionPolicy Bypass -File .\install.ps1             # rules: поставить правила
```

Результат: `eval/results/<runid>-<arm>.json` + таблица в консоли; при `-Arm both`
печатается сравнение (Δ = rules − baseline).

## Ограничения (честно)

- **Нужен агент.** Полный A/B требует headless-агента; харнесс его не содержит и не
  выбирает за тебя. Без агента доступны `-ValidateTasks`, `-ScoreOnly` и `-DryRun`.
- **Малая выборка.** 5 задач — это сигнал, а не статистика. Для выводов нужно 20+
  задач и несколько прогонов (агенты стохастичны), иначе Δ может быть шумом.
- **`unverifiedDone` — эвристика** по тексту лога: она ловит явные формулировки
  («готово», «done») и явные доказательства («exit code», «tests passed»), но не
  понимает сложных формулировок. Это дешёвый прокси, а не детектор лжи.
- **Только PowerShell-фикстуры.** Задачи не зависят от npm/pip, чтобы работать в
  любом окружении. Задачи на JS/Python — следующий шаг (нужны зафиксированные версии
  инструментов).
- **Архитектура не оценивается.** Любое «стало чище» здесь не измеряется: это требует
  человека или отдельной рубрики.
