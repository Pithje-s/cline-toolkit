# cline-toolkit

Единый репозиторий для конфигурации Cline: правила, навыки, воркфлоу и MCP-настройки.
Соберите один раз — используйте во всех проектах и делитесь с командой.

## Зачем это нужно

Каждый слой решает свою проблему:

- **`rules/`** — чтобы агент не спрашивал одно и то же. Глобальные правила
  (дисциплина кода, git, безопасность команд) загружаются в каждый диалог и
  избавляют от повторения одних и тех же инструкций.
- **`skills/`** — чтобы агент умел делать то, что не умеет «из коробки»:
  грамотное ревью кода (`independent-review`), разбор стектрейсов
  (`error-stack-analyzer`), исследование внешних источников (`external-research`),
  два архитектурных подхода перед крупной фичей (`design-twice`).
- **`workflows/memory-bank-*`** — чтобы не терять контекст между задачами.
  Агент ведёт «банк памяти» (продукт, архитектура, прогресс, решения), и в новой
  сессии быстро восстанавливает состояние проекта вместо «холодного старта».
- **`mcp/`** — чтобы подключать внешние инструменты (поиск, работа с ФС, git,
  память) по единому шаблону, не храня секреты в репозитории.

## До / После

**Без тулкита.** Каждая новая сессия начинается с нуля:

> — Ты умеешь делать код-ревью?
> — Да, могу посмотреть код.
> — А разобрать вот этот стектрейс?
> — Пришли, посмотрю.
> — И не забудь перед коммитом прогнать тесты и линтер, оформи коммит по
> Conventional Commits, не коммить .env…

И так каждый раз: одни и те же инструкции, потерянный контекст проекта,
секреты, которые кто-то однажды закоммитил по невнимательности.

**С тулкитом.** Правила, навыки и память уже загружены:

> — Use independent-review on this pull request.
> — Use repair-loop on this stack trace: `<вставка>`.
> — Load memory-bank context, мы продолжаем задачу про WeatherService.

Агент сразу знает правила проекта, умеет запускать нужные сценарии и помнит
контекст. Секреты лежат вне репозитория. Одна настройка — и так во всех проектах.

## Структура

| Папка | Содержимое | Что внутри |
|---|---|---|
| `rules/` | Глобальные правила поведения агента (`.md`) | 3 файла: базовое поведение, качество кода и git, рабочие процессы и поиск |
| `skills/` | Навыки (по одному `SKILL.md` на папку) | 9 навыков: ревью, разбор ошибок, research, починка, планирование, безопасность |
| `workflows/` | Воркфлоу-сценарии (`.md`) | Рабочие команды + система `memory-bank-*` (состояние проекта) |
| `mcp/` | Конфигурация MCP-серверов | Tavily (поиск) + заготовки fetch/filesystem/git/memory |

> **Полный справочник по каждому файлу — что делает, когда применять — в
> [CATALOG.md](CATALOG.md).**

## Установка: где лежат файлы

Актуальная раскладка Cline (по [официальной документации](https://docs.cline.bot/getting-started/config))
различает **глобальное** хранение (для всех приложений Cline на машине) и
**проектное** (хранится вместе с репозиторием).

| Слой | Глобально (все проекты) | В проекте (team-shared) |
|---|---|---|
| Правила | `~/.cline/` (напрямую) или `Documents/Cline/Rules` | `.clinerules/` или `.cline/rules/` |
| Воркфлоу | `~/.cline/workflows/` | `.clinerules/workflows/` |
| Навыки | `~/.cline/skills/` | `.cline/skills/` (рекомендуется), `.clinerules/skills/` |
| MCP-настройки | `~/.cline/data/settings/cline_mcp_settings.json` | — (через настройки workspace) |

На Windows `~` = `C:\Users\<USERNAME>`.

> Cline также читает старый формат `.clinerules/` (с подпапками `workflows/`,
> `skills/`, `hooks/`) и `AGENTS.md` в корне проекта — для обратной
> совместимости. Глобальный навык с тем же именем, что и проектный, имеет приоритет.

### Быстрая установка (глобально)

```powershell
# из корня склонированного репозитория
Copy-Item -Path .\rules\*.md     -Destination "$HOME\.cline\" -Force
Copy-Item -Path .\workflows\*.md -Destination "$HOME\.cline\workflows\" -Force
Copy-Item -Path .\skills\*       -Destination "$HOME\.cline\skills\" -Recurse -Force
Copy-Item -Path .\mcp\cline_mcp_settings.json -Destination "$HOME\.cline\data\settings\" -Force
```

Либо запустите готовый скрипт — он делает то же самое и дополнительно
**сохраняет существующий ключ Tavily** из старого конфига:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\install.ps1
```

## Автоустановка через ИИ-агента (промпт)

Не хотите раскладывать файлы руками? Скопируйте промпт ниже и отдайте его
Cline (или другому агенту) из корня склонированного репозитория — он сам
разберётся со структурой, создаст нужные папки и разложит файлы по местам,
не задев существующие настройки и не трогая секреты.

````text
Ты работаешь с репозиторием cline-toolkit — набором конфигурации для Cline
(правила, навыки/скиллы, воркфлоу и MCP-настройки). Твоя задача — установить
всё это в глобальные каталоги Cline на текущей машине.

Сначала изучи структуру репозитория (rules/, skills/, workflows/, mcp/) и README,
чтобы понять, что куда копируется. Затем выполни установку по правилам ниже.

Раскладка Cline (глобально):
- rules/*.md          -> ~/.cline/           (на Windows: C:\Users\<USER>\.cline\)
- workflows/*.md      -> ~/.cline/workflows/
- skills/*            -> ~/.cline/skills/     (рекурсивно, с подпапками)
- mcp/cline_mcp_settings.json -> ~/.cline/data/settings/cline_mcp_settings.json

Требования безопасности (ОБЯЗАТЕЛЬНО):
- НЕ копируй реальный API-ключ. В mcp/cline_mcp_settings.json ключ Tavily — это
  плейсхолдер YOUR_TAVILY_API_KEY. Если в целевом ~/.cline/data/settings/
  cline_mcp_settings.json уже есть рабочий ключ — сохрани его, не затирай.
  Для этого перед копированием проверь существующий файл: если в нём есть
  непустой tavilyApiKey, перенеси реальное значение ключа в новый конфиг,
  оставив остальные серверы из шаблона.
- Ничего не удаляй без подтверждения. Если папка уже существует — добавляй
  файлы поверх (Copy-Item -Force), не стирая остальное содержимое.
- Не коммить и не публикуй секреты.

Порядок действий:
1. Определи домашний каталог пользователя ($HOME на Windows = C:\Users\<USER>).
2. Создай недостающие папки: ~/.cline, ~/.cline/workflows, ~/.cline/skills,
   ~/.cline/data/settings (New-Item -ItemType Directory -Force).
3. Скопируй файлы по схеме выше. Для skills используй -Recurse.
4. Для MCP: если целевой конфиг уже существует и содержит рабочий ключ —
   сохрани ключ, добавив/обновив серверы из шаблона без перезаписи секрета.
   Если файла нет — скопируй шаблон как есть (с плейсхолдером ключа).
5. Проверь результат: выведи список установленных файлов и подтверди, что ключ
   Tavily либо остался плейсхолдером, либо был перенесён из старого конфига.
6. В конце кратко отчитайся: что скопировано, сколько файлов, и нужен ли
   пользователю ручной ввод ключа Tavily.

Используй PowerShell. Не используй Format-Table для вывода (он вешает терминал) —
выводи через ForEach-Object или Select-Object. Не запускай интерактивных команд.
````

> Промпт рассчитан на аккуратную установку: он сохраняет существующий ключ
> Tavily и не затирает чужие настройки. После установки перезапустите Cline,
> чтобы он подхватил новые правила, навыки и MCP-серверы.

## MCP-серверы

Файл `mcp/cline_mcp_settings.json` содержит несколько серверов:

| Сервер | Назначение | Статус |
|---|---|---|
| `tavily` | Веб-поиск и research с AI-результатами (нужен API-ключ) | включён (шаблон) |
| `fetch` | Загрузка и парсинг веб-страниц | заготовка (`disabled: true`) |
| `filesystem` | Ограниченный доступ к файловой системе | заготовка (`disabled: true`) |
| `git` | Операции с локальным git-репозиторием | заготовка (`disabled: true`) |
| `memory` | Долговременная память между сессиями | заготовка (`disabled: true`) |

Заготовки выключены через `"disabled": true`. Чтобы включить сервер — поставьте
`"disabled": false` и укажите реальные пути (например, для `filesystem` и `git`).

> JSON не поддерживает комментарии, поэтому описание каждого сервера вынесено
> в эту таблицу, а не в сам файл.

## Безопасность: API-ключ Tavily

В репозитории хранится **очищенный** шаблон MCP-конфига с плейсхолдером
`YOUR_TAVILY_API_KEY`. Реальный ключ в репозиторий НЕ коммитится.

Чтобы подключить Tavily локально:

1. Получите ключ на https://tavily.com (раздел API Keys).
2. В локальной копии `cline_mcp_settings.json` замените `YOUR_TAVILY_API_KEY`
   на свой ключ.

> Никогда не публикуйте реальный ключ в публичном репозитории — отзовите и
> перевыпустите его, если он был раскрыт.

## Рецепты: как вызывать skills и workflows

Навыки и воркфлоу вызываются обычным текстом в диалоге с агентом — Cline
подхватывает их автоматически.

**Skills (навыки):**

- Код-ревью: `Use independent-review on this pull request.`
- Разбор ошибки: `Use error-stack-analyzer on this stack trace: <вставка>.`
- Два подхода к архитектуре: `Use design-twice for <фича>, потом согласуем.`
- Внешний поиск: `Use external-research to find <тема>.`
- Проверка изменений: `Run verify-changes before committing.`

**Workflows (сценарии):**

- Новая сессия / восстановление контекста:
  `Load memory-bank context, продолжаем задачу про <фича>.`
- Зафиксировать архитектурное решение в начале работы над фичей:
  `Use memory-bank-decisions, я выбрал <подход>, потому что <причина>.`
- Починить по стектрейсу: `Use repair on this: <стектрейс>.`
- Перед коммитом: `Run precommit-check.`
- План большой задачи: `Use plan for <задача>.`

> Совет: в начале новой сессии сначала подгружайте `memory-bank-*` контекст —
> это даёт агенту состояние проекта и экономит время на повторное объяснение.

## Адаптация под себя и вклад

Репозиторий задуман как **отправная точка**, а не догма. Меняйте его под свой
стиль и делитесь улучшениями:

- **Правила** — сократите или расширьте `rules/*.md` под свои стандарты; при
  разветвлении контекста следуйте политике из `02-quality-git.md`.
- **Навыки** — добавляйте свои папки с `SKILL.md` (метаданные `name`/`description`
  + инструкции); Cline подхватит их автоматически из `~/.cline/skills/`.
- **Воркфлоу** — копируйте существующий `.md`, меняйте `description` и шаги;
  команды (`/plan`, `/review` и т.п.) создаются самим фактом наличия файла.
- **MCP** — включайте нужные серверы из шаблона или добавляйте свои, не
  коммитя секреты (см. «Безопасность»).

Если что-то из набора оказалось полезным — форкните, доработайте и открывайте
pull request. Чем универсальнее и качественнее конфиги, тем большую ценность
репозиторий несёт для сообщества Cline.
