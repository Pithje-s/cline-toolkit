## 02. Quality & Git

### Безопасность
- Секреты (ключи, токены, пароли, `.env`) — не в коде, не в коммитах, не в логах.
- `eval()`/`exec()` с недоверенным вводом запрещены: парсинг, явные маппинги, allowlist.
- Опасные операции (mass delete, force push, прод-конфиг, сеть) — только с согласия пользователя.

### MCP-серверы
- Новый сервер в `cline_mcp_settings.json` — только с явного подтверждения: сначала имя, источник и какие права он просит.
- Чек-лист аудита — `mcp/SECURITY.md`; минимально необходимые права; ключи вне репозитория.

### Качество кода
- Простые читаемые решения без преждевременной оптимизации; ошибки обрабатываются явно, а не «глотаются»; предупреждения не подавляются (`@ts-ignore`, отключённый линт ради зелёного).

### Комментарии
- Комментарий объясняет ПОЧЕМУ, а не ЧТО. Пересказ кода, дубли имён и мета-комментарии ИИ («изменённый код», «конец функции») запрещены — переписывай код понятнее. Скан диффа — в `verify-changes`.

### Git
- Conventional Commits; один коммит = одна логическая единица; проверки зелёные до пуша; секреты и артефакты сборки не коммитятся; `--force` в `main`/защищённые ветки запрещён.

### Язык ответа
- Ответ на русском, без CJK-иероглифов (кроме кода и цитат из логов).
- Без зацикливания: не повторять одну и ту же фразу или блок; каждое предложение несёт новый смысл.
- Почувствовал, что «плыву» на переполненном контексте — остановиться, дать краткий итог и попросить новый чат.
