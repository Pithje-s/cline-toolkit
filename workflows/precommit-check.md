Финальный чек-лист перед тем, как объявить задачу выполненной. Если хоть один пункт не выполнен — задача НЕ завершена.

## 0. Изменения применены к файлам?

- Каждый intended-файл реально изменён (`git --no-pager diff --stat`)
- Ни одной «обсуждённой, но не применённой» правки
- Если пункт не выполнен — применить сейчас, затем продолжить

## 1. Код проверен?

- [ ] Сборка проходит (`npm run build` / аналог)
- [ ] Тесты зелёные (`npm test` / аналог)
- [ ] Нет ошибок типов (`npx tsc --noEmit` / аналог)
- [ ] Линт чист (`npm run lint` / аналог)
- Вывод команд сохранён в файл и прочитан, код выхода = 0

## 2. Логика проверена?

- [ ] happy path работает
- [ ] граничные случаи обработаны
- [ ] ошибки обрабатываются корректно
- [ ] нет регрессий (полный набор тестов зелёный)

## 3. Качество проверено?

- [ ] нет отладочного кода (console.log, print, dbg!)
- [ ] нет закомментированного кода
- [ ] имена переменных/функций осмысленны
- [ ] секреты не в коде

## 4. Документация проверена?

- [ ] обновлены определения типов/экспорты при изменении сигнатур
- [ ] README/комментарии обновлены при изменении поведения

## 5. Каждое изменение доказано

- [ ] у каждого изменения есть доказательство (вывод команды / git diff / скриншот)
- [ ] статус: PASS или PARTIALLY VERIFIED с причиной

## 6. Git-дисциплина соблюдена?

- [ ] формат коммита — Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:` и т.д.)
- [ ] один коммит = одна логическая единица (не смешаны разные задачи)
- [ ] нет `git push --force` в main/master
- [ ] в коммите нет секретов, `.env`, ключей, артефактов сборки
- [ ] проверки зелёные до пуша

## 7. Zero Placeholders

- [ ] Заглушек нет по определению из `rules/01-core.md` (Zero Placeholders): `TODO`, псевдокод, `... existing code ...`, пустые тела — если scaffold не запрашивался явно.
- [ ] Каждый изменённый блок/функция выданы целиком, без сокращений.

## 8. Оркестрация следующего шага

- [ ] Сгенерирован следующий управляющий промпт через навык `next-step-orchestrator` (если задача завершена)

## 9. Действие вместо совета (для задач настройки системы/ОС/софта/игр)

- [ ] Если задача была про настройку системы — изменения реально применены через скрипт/файл/реестр, а НЕ выданы списком советов для пользователя
- [ ] Сделан бэкап (реестр/конфиг/файл или точка восстановления) ДО внесения изменений
- [ ] Есть доказательство применения (вывод команды, изменённый файл, git diff)
- [ ] Если что-то нельзя было автоматизировать — честно указано, что именно и почему (без молчаливой подмены советами)

## Если всё ок

Кратко перечисли: какие проверки прошли (с доказательствами), какие файлы изменены, что осталось (если есть).

## Если что-то не прошло

Не объявляй задачу выполненной. Запусти repair-цикл (workflow `repair` / skill `repair-loop`) до зелёного или честно сообщи, что именно не проверено и почему.
