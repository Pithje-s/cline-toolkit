При вызове `/verify` активируй навык `verify-changes`.

Тотальная проверка: правка не завершена, пока не применена к файлам и не подтверждена запуском.

## 1. Подтверди, что правки реальны (не только предложены)

- `git --no-pager diff --stat` и `git --no-pager diff <file>` — каждый нужный файл должен быть в диффе
- Для новых файлов: `Test-Path <path>` + `Get-Content <path> -Head 20`
- Если правки, которую ты «сделал», в диффе нет — примени её сейчас. НЕ отчитывайся «готово»

## 2. Подтверди, что это работает

Выбери сильнейшее доступное доказательство:
- Автотесты: `npm test *> test-out.txt; Write-Host "EXIT:$LASTEXITCODE"; Get-Content test-out.txt -Tail 30` (сборка/типы/линт аналогично)
- Ручной запуск: старт приложения/скрипта + журнал или скриншот
- Если запустить нечего: точечное чтение изменённого участка + цитата строк

## 3. Красно — чини и повтори

Если проверка упала: диагностируй, исправь, перезапусти. Цикл до зелёного или до лимита (см. workflow `repair`, skill `repair-loop`).

## 4. Отчёт с доказательствами

```
VERIFIED
- <file> изменён: <что> (доказательство: git diff / файл показан)
- <команда> запущена: <результат> (доказательство: код выхода / хвост вывода)
- Статус: PASS
```
Если что-то проверить невозможно:
```
PARTIALLY VERIFIED
- <file> изменён: <что>
- НЕ проверено: <что> потому что <причина>
- Для проверки: <команда>
```

Анти-паттерны: «примените эти изменения» (сделай сам), «должно работать» (запусти и покажи), «тесты не запускались» (запусти).

Детали — skill `verify-changes`.
