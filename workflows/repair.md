Путь до зелёного результата: каждый провал проверки — это сигнал к починке, а не к отчёту.

Те шаги, где проверка красная (тесты/сборка/линт/типы):

1. Запусти все проверки, собери вывод в файл, определи что упало
2. Диагностируй корневую причину (ожидалось / получено / почему)
3. Внеси минимальную правку — только под этот сбой, без рефакторинга
4. Перезапусти упавшую проверку (конкретную, не весь набор)
5. PASS -> шаг 6; FAIL -> шаг 2 с новой ошибкой
6. Прогони полный набор, чтобы поймать регрессии
7. Отчитаться ТОЛЬКО когда всё зелёное, с доказательствами (вывод, код выхода)

Лимиты: одно и то же 3 раза — стоп и к пользователю; 10 итераций всего — стоп. Новые ошибки от правки — откатить правку.

Детали и команды по типам проектов — skill `repair-loop`.

- Сначала прогони `manage_knowledge` (list sections), затем `knowledge_search`
- Для диагностики — `sequential-thinking` при множестве ошибок
- Каждая итерация = правка + повторный запуск, не отчёт
