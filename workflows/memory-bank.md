*Core Memory Bank System*

Версия: 1.0

## О проекте

Этот Memory Bank — централизованное хранилище знаний для разработки по спецификации. Он поддерживает чёткое понимание проекта всеми участниками и обеспечивает последовательность решений и хода работы.

## Структура

Memory Bank состоит из необходимых основных файлов и опциональных файлов контекста, каждый из которых служит определённой цели:

### Основные файлы (обязательные)

1. `memory-bank/product.md`
- Определяет проект и его цели
- Фиксирует, что строится и почему
- Объясняет ключевые функции
- Хранит высокоуровневые цели проекта

2. `memory-bank/activeContext.md`
- Текущий фокус работы
- Последние изменения
- Следующие шаги
- Активные текущие соображения
- Текущий контекст и состояние проекта

3. `memory-bank/progress.md`
- Что работает
- Что осталось сделать
- Текущий статус
- Известные проблемы
- Отслеживание хода работы

4. `memory-bank/nextTask.md`
- Следующая задача для выполнения
- Критерии приёмки
- Контекст и зависимости
- Заметки по реализации
- Контрольный список предусловий
- Текущий фокус внимания

5. `memory-bank/decisionsLog.md`
- Ключевые архитектурные решения
- Выбранные варианты и обоснование
- Компромиссы
- Альтернативы
- Последствия решения

6. `memory-bank/projectMap.md` (обязательный для незнакомых проектов)
- Архитектура проекта (стек, фреймворки)
- Дерево ключевых директорий и их назначение
- Список ключевых файлов (например: `src/auth.py` — отвечает за JWT и логин)
- Основные сущности и связи (Models/DB, API Endpoints, UI Components)
- Правило: при старте новой сессии с незнакомым проектом — сначала просканировать проект и создать `projectMap.md`, и только потом браться за задачи. Карта нужна для НАВИГАЦИИ, а не для слепой замены (номера строк меняются — читай актуальный код перед правкой).

### Опциональные файлы контекста

7. `memory-bank/productContext.md`
- Почему существует проект
- Как решаются проблемы
- Ожидаемый опыт пользователя
- Варианты использования
- Ограничения и предположения

8. `memory-bank/systemPatterns.md`
- Архитектура системы
- Ключевые технические решения
- Выбранные паттерны проектирования
- Компоненты и связи
- Модели данных и схемы

9. `memory-bank/techContext.md`
- Используемые технологии и фреймворки
- Зависимости
- Инструменты разработки
- Ограничения производительности
- Соображения безопасности

## Основные потоки

### Plan Mode

Чтение всех основных файлов + основного файла плана (с небольшой проверкой) → согласование плана → запись плана в соответствующий файл → проверка плана → утверждение плана пользователем → запись утверждённого плана в активный контекст / план → переход в режим Act

### Act Mode

Чтение активного контекста + основного файла → запрос изменений у пользователя → предложение плана → запись изменений в память → выполнение плана → запись результата → обновление активного контекста / прогресса → переход в режим Plan (или Ask по запросу)

## Управление памятью

1. Решения: все ключевые архитектурные выборы фиксируются в `decisionsLog.md` с датой, вариантами, обоснованием и последствиями
2. Прогресс: отслеживается в `progress.md` и обновляется после каждой значимой работы
3. Контекст: `activeContext.md` служит рабочей памятью о текущем состоянии
4. Шаблоны: повторяющиеся решения выносятся в `systemPatterns.md`

## Принципы обновления

- ВСЕГДА обновлять активный контекст после значимых изменений
- НЕ удалять информацию — добавлять новые записи
- Сохранять хронологический порядок в логах
- Используемые инструменты: `update_memory_bank`, `read_file`

## Целевая аудитория

Разработчики, тимлиды и архитекторы, работающие над проектом

## Оптимизация контекста и кэширование

- При использовании моделей Gemini через OpenRouter необходимо вручную включить чекбокс "Enable Prompt Caching" в настройках провайдера Cline. Это снижает стоимость повторяющихся запросов.
- Для моделей, требующих явных `cache_control` (например, Qwen), используй соответствующие настройки провайдера, если они доступны.
- Стабилизируй системные промпты и схемы инструментов, чтобы максимизировать попадания в кэш (не меняй их без необходимости между запросами).
- Следи за метрикой `cached_tokens` в ответах API: если она равна 0, кэш не работает — проверь настройки провайдера и модель.
