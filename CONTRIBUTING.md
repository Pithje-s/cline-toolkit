# Вклад в cline-toolkit

Спасибо, что хотите улучшить набор! Репозиторий — это конфигурация для Cline
(правила, навыки, воркфлоу, MCP), поэтому «код» здесь — в основном Markdown и JSON.
Ценятся ясность, переносимость и безопасность.

## Как устроен репозиторий

| Папка | Что кладут | Правила оформления |
|---|---|---|
| `rules/` | Глобальные правила (`.md`) | Один файл = одна тема (01-core, 02-quality-git, 03-workflow-search) |
| `skills/` | Навык = папка с `SKILL.md` | Обязательны `name:` и `description:` в YAML-frontmatter |
| `workflows/` | Воркфлоу (`.md`) | Обязателен `description:` во frontmatter |
| `mcp/` | `cline_mcp_settings.json` | Без реальных секретов — только плейсхолдеры |

Полный справочник по содержимому — в [CATALOG.md](CATALOG.md).

## Чек-лист перед pull request

1. **Валидация проходит.** Запустите `powershell.exe -ExecutionPolicy Bypass -File .\validate.ps1` — должно быть `RESULT: PASS`.
2. **Без секретов.** Никаких реальных ключей/токенов. Ключи — только плейсхолдеры (`YOUR_TAVILY_API_KEY`).
3. **Frontmatter корректен.** У нового навыка/воркфлоу есть YAML-шапка с `name:`/`description:`.
4. **Без CJK-иероглифов** в тексте (проверяет валидатор).
5. **Без заглушек.** Никаких `TODO: implement`, `... existing code ...`, пустых тел.
6. **Переносимость.** Изменения не завязаны жёстко на один стиль/язык — либо это явно оговорено.
7. **Conventional Commits** в истории: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`, `perf:`, `build:`, `ci:`.

## Предложение изменений в правила

Правила влияют на поведение агента у всех, кто их установит. Поэтому:

- Крупные/поведенческие изменения обсуждайте в issue **до** PR.
- Описывайте мотивацию: какую боль закрывает правило, не конфликтует ли оно с существующими.
- По возможности делайте поведение параметризуемым (см. «Кастомизация» в README), а не хардкодьте.

## Сообщение об ошибке

Откройте issue и укажите: что ожидалось, что произошло, версия Cline, ОС, фрагмент
конфига/лога (без секретов). Для проблем с поведением агента полезно приложить
минимальный воспроизводящий диалог.
